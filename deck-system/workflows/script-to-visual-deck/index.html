Workflow

Script to Visual Deck

Company/Purpose Formatの有無を確認し、台本をContent Pack化し、Visual PlanとAsset Promptsを経てHTMLスライドへ合成する標準工程です。

0

Format Check

既存Company/Purpose Formatが使えるかを確認。なければPlain Baseから作成する分岐へ進みます。

1

Content Pack

既存のscript-inputとslide-planを正式化し、台本をbrief、narrative、slide-plan、speaker-notes、claimsへ分解します。

2

Visual Plan

各スライドにpatternとvisual slotを割り当て、image2/SVG/icon/photo/noneを決めます。

3

Deck & QA

Asset Promptsを生成し、HTMLへ差し込み、全ページ監査とスクショ確認を通します。

Artifacts

工程間の受け渡しは会話メモではなく、必ず成果物に残します。

workflow.md全体工程とゲート。 artifacts.md成果物契約。 skill-map.md親ワークフローと原子スキルの分割。 format-check.mdFormatあり/なし分岐。 content-pack.md台本から作るContent Pack。 slide-plan.mdスライド単位の計画表。 visual-plan.jsonレイアウトと視覚スロットの計画。 asset-prompts.json画像/SVG生成プロンプト。 qa-report.md最終監査レポート。 deck-format-checkFormatあり/なしを判定するStep 0の原子スキル仕様。 script-to-content-pack既存の台本入力とslide-planをContent Packへ正規化するStep 2の原子スキル仕様。 Kikai exampleKikai visual-rich seminarでのFormat Checkサンプル。 Kikai Content PackKikai既存デックを新しいContent Pack契約へ変換した34枚の実地サンプル。

Entry Rule

Company / Purpose Format がある場合は台本工程から開始します。ない場合だけ、Plain Base → Company / Purpose Format の工程を先に実行します。

Current Kikai Status

kikai-business-visual-ppt は視覚重視デックの現行候補です。固定画像スロット、brand visual style、prompt template、QAを持ちますが、正式なCompany Formatとして扱う前に正規化表に沿ってレビューします。
