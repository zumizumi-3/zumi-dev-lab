# Page Visual Slots

This file is the page-by-page visual insertion contract for `plain-business-visual-ppt`.

The rule after the 2026-05-18 re-audit is stricter than the first pass: a slot must name the **page element** and the **semantic role** of the asset. Ordinal names such as `card-1` are allowed only as an anchor prefix for the renderer; the rest of the slot must explain what that card, row, node, or SVG part means.

The matching HTML section carries `data-visual-required`, `data-visual-insert`, and `data-visual-spec`. The JSON version is `page-visual-slots.json`.

## Enforcement Rules

- Do not specify `body`, `body-center`, `side-panel`, `card`, or `card whole` as the instruction unless the page is explicitly a single image2-frame exception.
- For card-like pages, the slot must say what the card represents: conclusion, evidence, next action, customer, competitor, plan A, risk, cost, etc.
- For row/table pages, target the row, column, status cell, commentary frame, or mini-chart location. Do not convert the whole table to an image.
- For SVG pages, specify diagram parts: center node, branch, axis, ring, gate, callout, level, dependency, or card.
- `none` pages are still reviewed. Their density must come from tables, comments, units, labels, or larger editable text rather than decorative visuals.
- Generated image2 assets must be one file per semantic slot. Do not generate a single atlas and crop/stretch it into unrelated cards.
