PB-01 / Agenda Meeting or proposal flow

会議・提案の流れは番号付きレーンで先に固定する

各項目に目的と所要時間を持たせ、後続スライドの構成を崩さない。

01前提確認5 min
02現状と課題10 min
03施策案と比較15 min
04実行計画10 min
05決定事項5 min
Agenda keeps body slides aligned to the meeting decision. PB-01
PB-02 / Executive Summary Key points and implication

最初に判断材料を3点へ圧縮する

業務PPTの要約ページは、結論、根拠、次アクションを同じ粒度で並べる。

Conclusion継続

主要KPIは維持。改善余地は流入品質に集中。

Evidence+12%

問い合わせは増加、商談化率は横ばい。

Next2案

訴求軸と比較資料を先に改訂。

Use when the deck needs a management-ready first answer. PB-02
PB-03 / Issue and Direction Problem solving

課題は「症状」「原因」「対応方針」に分ける

分析スライドでは、いきなり施策に入らず、判断の根拠を短く並べる。

1 症状

KPIが横ばいになり、直近施策の改善幅が小さい。

2 原因

流入、転換、継続のうち、初回接点の質に差が出ている。

3 対応方針

訴求軸を再整理し、優先チャネルから検証する。

Main slide density: 3 lanes, 1 claim per lane. PB-03
PB-04 / 3C Analysis Environment analysis

環境分析は3つの観点を同じ粒度で比較する

各レーンの見出し、観察、示唆を揃えることで、次の打ち手へ接続しやすくする。

Customer

意思決定までの情報収集期間が長く、比較材料を求めている。

Competitor

価格訴求よりも導入後の支援範囲を強く打ち出している。

Company

実績と運用知見はあるが、初回資料で十分に伝わっていない。

Implication: 価格差の説明より先に、導入後の成果と支援体制を見せる。

Use a bottom implication bar when the analysis must connect to action. PB-04

KGIから施策までを一枚でつなげる

目標、管理指標、成功要因、実行項目の対応関係を明確にする。

KGI四半期売上目標の達成

Keep each node short; detailed formulas belong in notes. PB-05

定例会議資料では、進捗率だけでなく、遅延理由と打ち手まで同じ行に置く。

PB-10 / Competitor Comparison Criteria matrix

競合比較は評価軸を先に固定する

比較表では列ごとの強弱よりも、意思決定に必要な評価軸を揃える。

評価軸別の競合比較
評価軸自社A社B社示唆
導入支援強中弱初期伴走を前面に出す
価格中低中単価ではなく総コストで説明
実績強中中業種別事例を補強
拡張性中中強将来要件の範囲を確認
Use neutral status chips; apply company colors only in a derived format. PB-10
PB-11 / Proposal Options Options and recommendation

選択肢比較は推奨案がわかる形で並べる

案A/B/Cを同じ項目で比較し、推奨理由と採用条件を最後に置く。

Plan A / 最小改善

短期で実行可能。効果は限定的だがリスクが低い。

Plan B / 推奨

主要課題に集中。効果と負荷のバランスが良い。

Plan C / 全面刷新

効果は大きいが、準備期間と関係者調整が必要。

Recommendation: まずPlan Bで検証し、結果が一定水準を超えたらPlan Cへ拡張する。

Options slides must expose the recommended path. PB-11

最後は担当・期限・依存関係まで落とす

会議資料では、結論だけでなく次に誰が何を進めるかを明示する。

次アクション管理
アクション担当期限依存状態
訴求軸の再整理企画5/22顧客ヒアリング未着手
比較資料の改訂営業5/26競合情報進行中
検証チャネル選定マーケ5/29予算確認確認中
次回報告PM6/05上記完了予定
Action rows should be concrete enough to move into a tracker. PB-12

研修資料は目的から実践確認までを一本化する

PB-16 / SWOT 2x2 Quadrant analysis

2x2分析は象限ごとに示唆を持たせる

SWOTや優先度整理では、象限名だけで終わらせず、次の判断に使える一文を入れる。

Strength

既存実績と運用知見があり、導入後支援を説明できる。

Weakness

初回資料で差別化が伝わりにくく、比較時に埋もれる。

Opportunity

比較検討の長期化により、支援体制の説明価値が上がる。

Threat

低価格訴求の競合が増え、単価だけで比較される。

Use for SWOT, priority, risk/impact, and effort/value analysis. PB-16
PB-17 / Before After Current and target state

Before / After は変化の理由まで添える

現状と理想を並べるだけでなく、何が変わるから成果につながるのかを明示する。

Before

提案内容は説明できるが、意思決定者の論点と接続していない。

Change

判断軸、比較材料、導入後支援を一枚で見える化する。

After

担当者が上位者へ説明しやすくなり、検討の停滞を減らす。

Source decks often use before/after as the bridge to proposal options. PB-17
PB-18 / Interview Voice Person, quote, implication

人物・声・示唆を分けると事例ページになる

採用、研修、顧客事例では、誰の発言か、何を示しているかを混ぜない。

PersonRole

職種、部署、関係性を短く記載。

Voice

引用やコメントは短く。長い背景はノートへ分離する。

Implication

この声が資料全体の主張にどう効くかを書く。

No real person names or client quotes are included in this base. PB-18

選考・承認プロセスは通過条件を併記する

採用説明、稟議、導入手順では、ステップだけでなく各ゲートの確認事項を置く。

01 Entry対象・条件を確認
02 Review資料と前提を確認
03 Interview論点をすり合わせ
04 Decision合否・承認を判断
05 Start開始条件を確定
Process rail patterns should include gate conditions. PB-19

章の冒頭では論点と到達点を同時に示す

章タイトルだけで止めず、どの順番で判断材料を見るかを短い目次として置く。

01前提と制約対象範囲

PB-21 / Standard Body Canvas Title, context, free body area

標準本文ページは上詰めにせず、下げた本文領域で受ける

PPTXの本文プレースホルダーはタイトル直下に存在するが、本文として扱い、リード文のように詰め込まない。

自由配置の本文領域図解、箇条書き、表、スクリーンショットを1つの主構造として置く。
Use this as the fallback when the imported PPTX has a normal body placeholder. PB-21
PB-22 / Two Column Agenda Parallel topics

論点が多い目次は左右2列で粒度を揃える

検討項目と確認項目を分けると、会議の流れと資料の章立てを同時に読める。

01背景5 min
02課題10 min
03仮説10 min
04施策15 min
05体制8 min
06決定7 min
Use for long meeting agendas, proposal chapters, and workshop modules. PB-22
PB-23 / Three Step Horizontal Method or approach

3段階の進め方は横方向に因果をつなぐ

調査、設計、実行のような流れは、左から右へ読み、最後に判断条件を添える。

1整理

目的、対象、制約を分け、前提のズレをなくす。

2設計

選択肢と評価軸を置き、比較可能な形にする。

3実行

担当、期限、確認方法まで落として開始する。

Gate: 各段階の成果物が次段階の入力になるように置く。

Use for methods, migration steps, onboarding, and approval sequences. PB-23
PB-24 / Left Label Right Description Definitions and explanations

説明項目は左ラベル、右本文で読ませる

用語定義、前提条件、検討軸は、箇条書きよりもラベル付きの横長行で整理する。

対象今回の検討範囲に含める部署、期間、顧客セグメントを明示する。
除外未確定の機能、別プロジェクトの論点、今期対象外の施策を分ける。
基準評価軸、優先順位、承認条件を同じ粒度で記載する。
出力このページの結論が次ページの比較表または実行計画に渡る。
Use for glossary, scope, assumptions, and policy explanations. PB-24
PB-25 / Requirements Stack Requests and constraints

依頼事項は要件、根拠、期限を一行にまとめる

発注、社内依頼、確認事項は、読んだ人が次の行動を迷わない形にする。

Must公開前に法務確認が必要。修正期限は5/24、確認者は事業責任者。
Should比較表は3案に絞り、評価軸を価格、効果、運用負荷に固定する。
Could余力があれば導入事例を1件追加し、営業説明の補助資料にする。
Risk素材未確定のため、デザイン確定は本文承認後に切り分ける。
Use for requirement sheets, vendor requests, and internal action asks. PB-25
PB-26 / Hub Tree Diagram Central concept and branches

中心概念と周辺要素はハブ型で関係を示す

テンプレート系PPTで多い図解は、中心に主張、左右に原因と打ち手を置くと読みやすい。

背景市場変化、顧客行動、社内制約
課題接点不足、説明不足、運用負荷
中心メッセージ
施策訴求再設計、資料改訂、検証
効果理解促進、停滞削減、再現性
Use for object-built diagrams where labels are not slide titles. PB-26
PB-27 / VS Comparison Contrasting alternatives

対立案は同じ項目で見比べられるようにする

左右の見出しだけでなく、判断軸、メリット、リスクを揃えて差分を明確にする。

現行維持

短期負荷は低いが、比較検討時の説明不足が残る。

既存運用を活かせる一方、改善幅は限定的。

VS
刷新案

資料体系を再設計し、判断軸と導入後支援を前面に出す。

初期工数は必要だが、営業説明の再現性が高まる。

Use for before/after, buy/build, internal/external, and old/new comparisons. PB-27
