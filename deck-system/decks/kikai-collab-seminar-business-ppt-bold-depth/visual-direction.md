# Bold Depth White/Orange Visual Direction

## Purpose

既存の Bold White Orange 版を上書きせずに比較するための別デザイン。既存の構成と34枚の流れは保ちつつ、より大きい文字、白背景、Kikai濃オレンジ基調、本文の濃いグレー、カードの線・影・濃淡、画像とSVGの露出を増やして、セミナー投影時に一目で意味が取れる強い見た目へ寄せる。

## Color Palette

| Role | Color | Usage |
| --- | --- | --- |
| Corporate primary | `#FC754A` | タイトル下線、左バー、番号、強調語、主要アクセント |
| Primary soft | `#FEF8F6` | featureカード、内側カード、タグ、薄い面の濃淡 |
| Text | `#343230` / current dark gray | タイトル、本文、カード見出し |
| Page background | `#FFFFFF` | スライド全体の背景。薄い色面で塗らない |
| One-point blue | `#6697EA` / `#F4F8FD` | 比較・第2項目・注意の整理など、オレンジだけで単調な場合に限定 |
| One-point green | `#69B086` / `#F5FAF8` | 成果・完了・再現性など、意味がある場合に限定 |

ワンポイントカラーは多用せず、オレンジとグレーだけでは比較軸や状態差が読み取りにくい箇所に限定する。

## Design Rules

- タイトルとリードは現状版より大きく、強い下線で視線誘導する。
- 主色は白背景と濃いグレー、補助色は `#FC754A` の濃オレンジ。Bordeaux/Gold系の見え方には寄せない。
- 画像アセットは既存の `kikai-collab-seminar-business-ppt-bold/assets/generated/` を参照し、同じ画像をこのデック内に複製しない。
- 表紙、章扉、ルート、クロージングには画像ポスターを追加する。
- 各スライド背景は白を基本にし、密度は背景色ではなく、意味のあるimage2画像、単色SVG、カード内図解、番号、注釈で上げる。
- カード、表、図解は太い罫線、強いfeature面、明確な番号で見せる。
- Bodyの可読性は上げるが、色面は増やしすぎない。White / Dark Gray / `#FC754A` Orange の統一感を保ち、SVG図解・薄い画像リボン・意味のある背景図で派手さを出す。
- Body本文は投影時の可読性を優先し、通常本文を20px以上、カード見出しを30px前後、箇条書きを18px前後まで上げる。行間は詰めすぎず、本文はおおむね1.4以上を基準にする。
- 参照画像 `../kikai-collab-seminar-business-ppt-bold/assets/generated/reference-monoline.png` はレイアウト模倣ではなく、単色系線画SVG、淡い生成画像テクスチャ、番号丸、余白に意味を持たせる装飾密度の参考として使う。特にP05/P10/P13は薄い画像の置き方から、文脈に合う構造図・コールアウトへ作り替える。
- カード型UIの中には、項目ごとに切り出した個別のimage2生成アセットを差し込み、共通アトラス背景の使い回しや縦横比の圧縮を避ける。`object-fit` と `aspect-ratio` で、横長カード、正方形寄りカード、P19右下アイコンを別々に扱う。登壇者紹介は実写真 `../kikai-collab-seminar-business-ppt-bold/assets/generated/sawada-photo.png` を使う。
- 汎用のグラフ風SVG、セキュリティマーク、右下の共通飾り、意味のない棒線は使わない。特にP04/P06/P16/P17/P26のような説明カードでは、棒グラフ風の装飾より、アイコン、タグ、矢印、プロセス、実写/生成画像で意味を補強する。

## Next Run Playbook

プレーンから同等品質へ再生成する場合は、最初に「フォーマット化」と「資料作成」を分けて指示する。プレーンへ戻す場合も、完成版の見た目を直接移植するのではなく、完成版から抽出した判断ルールを目的別フォーマットとして再適用する。

### First Prompt Template

```text
プレーンフォーマットは上書きせず、別バージョンとして企業/用途別フォーマットを作成してください。
基本構造は header / title / optional lead / body / footer です。
body は lead がある場合は lead 下から footer 上まで、lead がない場合は title 下から footer 上までの縦中央に配置してください。
背景は白、本文は濃いグレー、アクセントはKikaiロゴの濃オレンジ `#FC754A` を主軸にし、Gold/Bordeaux/赤い色面へ寄せないでください。
派手さは背景色ではなく、意味のある image2 画像、カード内画像、単色SVG図解、番号、注釈、情報密度で出してください。
全ページで、画像追加要否、既存画像の適切性、レイアウト妥当性を判定し、必要な場合はレイアウト変更と画像差し替えまで実施してください。
画像やSVGはページ/項目ごとに個別生成し、共通画像の使い回しや縦横比の潰れを避けてください。
```

### Recommended Sequence

1. **Source inventory**: プレーン、企業ロゴ、写真、参照PPT、台本、既存デッキを分けて読み込み、上書き禁止の対象を明示する。
2. **Format extraction**: 表紙、章扉、左右分割、3カード、4カード、比較、表、プロセス、ループ、ロードマップ、クロージングを最低構図として登録する。
3. **Brand pack**: 白背景、濃いグレー本文、`#FC754A` Orangeアクセント、ロゴ配置、ヘッダー/タイトル/下線/フッターの距離を先に決める。
4. **Content plan**: 各ページのコアメッセージ、補足情報、必要な視覚表現、話者メモを1ページずつ決める。元のGit構成に引きずられすぎない。
5. **Density pass**: 情報が薄いページは、箇条書き、比較軸、補足カード、ミニ図解、数値、CTAを足して密度を上げる。
6. **Visual pass**: image2はページ単位・カード単位で作る。横長、正方形、右下アイコン、人物写真、章扉画像など用途ごとに縦横比を指定する。
7. **Diagram pass**: SVGは単なる装飾ではなく、ルート、品質ゲート、案件化、比較、リスク、コミュニティの構造が読める説明図に限定する。
8. **Polish pass**: 全ページをスクショで見て、画像重複、縦横比の潰れ、カード内の位置ずれ、不要な汎用SVG、余白過多、文字サイズ不足を潰す。
9. **Page-by-page audit**: 最後はコンタクトシートだけで終わらせず、問題が出やすいページを個別表示で確認する。P04/P06/P16/P17/P26の汎用棒線、P12/P14/P21/P25/P34の余白と単調カード、表紙ロゴの枠感は必ず確認する。

### Quality Gates

- Bodyの中心は、スライド全体ではなく「Bodyに使える縦空間」の中央にある。
- 1枚1メッセージだが、投影に耐える情報密度がある。
- 画像は「それが何を表しているか」を説明できる。説明できない画像は差し替える。
- 同じ画像を別文脈で使い回さない。似た画像が必要な場合も構図、モチーフ、縦横比を変える。
- カード内画像はカードの意味に対応している。汎用背景や潰れたアトラス画像で埋めない。
- SVGは線画・図解・アイコンとして統一感がある。グラフ風、盾風、右下飾りなどの汎用装飾を散らさない。
- 色面で派手にしない。白背景、余白、文字サイズ、`#FC754A`のアクセント、画像密度で見せる。
- 表紙、章扉、クロージングは単なる余白ではなく、資料全体の印象と行動を決めるページとして別途確認する。
